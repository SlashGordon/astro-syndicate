dev.to has no public image-upload endpoint, so this integration resolves
local images to public URLs itself before a post goes out.

## The same image, twice

Referencing the same file twice only costs one upload - the second
occurrence is served from the pipeline's own cache:

## MDX-flavored content survives untouched

This file is `.mdx`, so it can hold JSX-like markup such as
<Badge>experimental</Badge> or an expression like <code>{'{2 + 2}'}</code>.
None of that confuses the syndication integration - it reads this file as
plain text via `gray-matter`, the same way it reads a `.md` file.
